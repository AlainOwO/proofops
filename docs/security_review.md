## Coverage and confirmed controls

- **Routes and roles:** `AuthenticationBoundary` defaults HTTP routes to authenticated access, including OpenAPI/docs and future routes. Only `GET /healthz` and the login challenge/login are public in ordinary mode. Workspace writes require admin in the backend. Login and CSRF-protected logout are deliberate identity-management exceptions to the rule that viewer workspace POST/PUT/PATCH/DELETE requests receive 403. The existing endpoint/method matrix fails on omitted routes. There are no current WebSocket routes.
- **IDOR and demo access:** Authenticated users share one workspace by documented design; a viewer can read any workspace review/export. There is no tenant/owner boundary to bypass. This is unsuitable for mutually private teams without additional authorization. Anonymous demo reads require explicit seeded membership and unchanged report/explanation/input hashes. Arbitrary imports, private drafts, billing, accounting, dispositions and docs are excluded; unsafe methods are rejected even for an existing admin session.
- **Sessions:** Argon2id uses 64 MiB, three iterations, parallelism two and random salts. Session tokens are random 256-bit opaque values, stored only as keyed digests. Cookies are HttpOnly, host-only, Path=/, SameSite=Lax, have absolute expiration/Max-Age, and use Secure plus `__Host-` in hosted mode. Login rotates the browser's previous session; logout deletes the stored session. Password rotation/disabling revokes all user sessions; roles/active status are re-read on requests. No session-fixation or logout-reuse bypass was identified. Local HTTP intentionally uses non-Secure cookies.
- **CSRF/CORS/origin:** Login has a signed, expiring double-submit challenge; authenticated unsafe methods require a session-bound `X-CSRF-Token`. Origin omission does not bypass token validation. CORS uses exact origins with credentials, startup rejects wildcard/non-HTTPS hosted origins, and Host validation is enabled. Configured preflights negotiate access without executing a handler. Proxy-header trust is disabled, so an arbitrary `X-Forwarded-For` cannot choose a fresh login bucket. Header deployment gaps are SR-07.
- **Imports:** Compressed body/ZIP bounds default to 5 MiB, each expanded member to 1 MiB, and entry count to 24; total expansion is also bounded. ZIPs are read in memory, never extracted; only exact supported filenames are accepted, with duplicate, symlink, encrypted, absolute and traversal paths rejected. Manifest hashes detect byte changes but are not signatures proving source authenticity. JSON rejects duplicate keys, non-finite constants and deep/large structures; normalization caps resource changes at 200. Pydantic bounds supported records. Aggregate parser/concurrency limitations are SR-06. YAML and uploaded Rego are not accepted input formats.
- **SQL/commands:** Runtime queries use SQLAlchemy/psycopg parameters. Dynamic SQL identifiers in tests are generated from application metadata. The worker does **not** invoke Terraform or execute imported plans. Conftest runs a fixed, trusted template and JSON data through an argument vector with `shell=False` and a 10-second invocation timeout. Imported/model guard specifications must equal the approved draft; no route activates a guard or deploys infrastructure. The optional Terraform installers/configuration and evaluator/measurement scripts are operator tools, not remotely selectable worker commands.
- **Secrets/history/logging:** No real provider-key or private-key block was detected in scanned text history. The public historical database credential is SR-01. `.env` and browser credentials are ignored and mode 0600 locally; root Docker context exclusions cover environment files/artifacts. Main backend images copy explicit application paths and do not copy `.env`. Worker/provider errors generally retain error classes rather than raw bodies. Redaction limitations are SR-02/SR-03; frontend context exclusions are SR-11. Both historical PDFs (4 and 28 pages) were text-extracted and all eight historical PNGs were OCR-processed locally. These checks found no additional credential-pattern or private-value matches; PNG metadata was empty. Pattern/OCR checks can miss unrecognized secrets. Arbitrary unlabelled secrets must still not be placed in metadata or selected model facts.
- **Docker/deploy:** Observed published local ports are `127.0.0.1:5173`, `127.0.0.1:8000`, `127.0.0.1:55432`, and the optional workload at `127.0.0.1:8080`. Internal `0.0.0.0` listeners make container networking work; they do not by themselves publish on every host interface. Public TLS, certificate management and HSTS are not provisioned. Terraform defaults to zero tasks, private subnets and no public task IP. The independent arithmetic workload's optional token is unset by default; its unauthenticated synthetic routes/metrics must stay isolated from real data.
- **AI authority and privacy:** AI is off by default and needs provider/model allowlisting, keys, explicit live preference and positive budgets. Context/output size, attempts, timeouts and reservations are bounded; adapters expose no tools, URL fetch, shell, Terraform or deployment capability. OpenAI requests set `store=False`; that alone is not a provider-wide retention guarantee. `review()` computes the decision first, `validate_explanation()` requires identical outcome/finding codes and typed cited values, and the worker persists the original report separately. Guard proposals must equal the trusted draft. Thus an AI explanation cannot change the actual decision or active policy in these code paths. Prompt injection and misleading prose are still distinct risks, covered by SR-03/SR-13. Live mode necessarily sends the explicitly selected facts to the configured provider.

## Login lockout answer

The limits are **both per normalized username and per connection peer**, persisted in PostgreSQL and shared across processes/restarts. Defaults are five failed account attempts and 60 peer attempts in a 900-second window. Unknown usernames also have counters and a dummy Argon2 verification. A blocked account is rejected before checking whether the supplied password is correct. An attacker can therefore deny new login to the real admin across IPs for 15 minutes, and repeat after expiry. Requests during the active block do not extend it. Existing sessions and the local operator CLI remain available. Behind the supplied Nginx proxy, the peer is Nginx, so different clients also share its bucket. SR-04 addresses storage exhaustion; it does not claim to solve SR-05's lockout/recovery design tradeoff.
